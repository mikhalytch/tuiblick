# tuiblick — manual

Short usage + manual test checklist (spec §§9–10). Unit gate
(`cargo fmt --check && cargo clippy -- -D warnings && cargo test`)
covers parsers and state transitions; everything below needs a real
box with `awg-quick`, `openvpn`, and sudo — macOS (both backends) or
Linux (AmneziaWG only; OpenVPN is not checked on Linux so far — see the Linux
note in the README).

## Setup

```sh
cargo build
./target/debug/tuiblick
```

Needs: macOS or Linux, a terminal with at least 80x24
(Terminal.app / iTerm2 / tmux on macOS, any xterm-compatible terminal or
tmux on Linux).
No shell is ever invoked — backend commands run as argv arrays.

Backend packages (macOS: both backends; Linux: AmneziaWG only):
`awg-quick` / `awg`, `openvpn` (not checked on Linux so far), `curl` (exit-IP probe),
plus `dig` for the OpenDNS fallback probe (optional: `bind` on
Arch/Manjaro, `dnsutils` on Debian/Ubuntu, `bind-utils` on Fedora —
without it a failed `curl` probe simply reports `unknown`). Route probing
needs `iproute2` on Linux (preinstalled on most distros; macOS uses the
built-in `route`). On Linux, `awg-quick` applies `DNS =` lines via
`resolvconf` — install a provider (`openresolv` on Arch/Manjaro) or
connects using DNS configs fail.

## Linux DNS pitfall: `resolvconf: signature mismatch`

If an AWG connect fails with `resolvconf: signature mismatch:
/etc/resolv.conf`, something else owns that file — usually NetworkManager
writing it directly, which breaks openresolv's signature. This is not an
`awg-quick` bug: since openresolv 3.17 it refuses to touch a foreign
`/etc/resolv.conf` (previously it silently overwrote it), so the same
`wg-quick`/`awg-quick` flow that worked before now aborts — see the
[Arch forum thread](https://bbs.archlinux.org/viewtopic.php?id=306639)
for the identical failure and resolution. Check with
`ls -l /etc/resolv.conf` (a managed file carries a `# Generated by
resolvconf` header; a foreign one is just `nameserver …` lines) and
`systemctl is-active NetworkManager`. The durable fix is to route
NetworkManager through resolvconf via a drop-in (preferred over editing
the main file — it survives package updates):

```sh
printf '[main]\nrc-manager=resolvconf\n' | sudo tee /etc/NetworkManager/conf.d/rc-manager.conf
```

then flush stale registrations (`sudo resolvconf -d awg0 -f`, or whatever
interface is listed by `resolvconf -l`), `sudo systemctl restart
NetworkManager` (briefly drops the network; a reboot works too), and
confirm `cat /etc/resolv.conf` shows the resolvconf header before
retrying the connect. Retrying without this just fails the same way —
`awg-quick` aborts on the `resolvconf -a` error and tears the interface
back down. (Removing the `DNS =` line from the profile also sidesteps
the failure, but then nothing applies the VPN's DNS servers.)

## Linux DNS pitfall, part 2: another VPN client restoring backups

A second writer can undo the repair at any time: some third-party VPN
clients snapshot `/etc/resolv.conf` on connect and restore the snapshot
on disconnect. Observed live with `wgtunnel-daemon` (WG Tunnel), which
logs `Resolv: Restored original /etc/resolv.conf from backup` on every
disconnect — each restore brings back the pre-repair bare file and the
next `awg-quick up` fails with `signature mismatch` again. Diagnose with
`journalctl | grep -i "restored original"` and file mtime (`ls -l
/etc/resolv.conf`) correlated with your disconnects. Fixes, in order of
preference: a "don't manage DNS" option in that client's settings; one
repair-then-connect-disconnect cycle with the healthy file in place (if
the client snapshots at connect time, its backup becomes the managed
file and the loop ends); otherwise re-run `sudo resolvconf -u` after
each of that client's disconnects before using `awg-quick`.

## Config root

tuiblick uses `$XDG_CONFIG_HOME/tuiblick/` on every platform, including macOS.
`XDG_CONFIG_HOME` must be an absolute base directory, without the `tuiblick`
suffix. If it is unset, empty, or relative, the base defaults to `~/.config/`.
The old app-specific config override is no longer used.
See the [XDG Base Directory Specification](https://specifications.freedesktop.org/basedir/0.8/).

```text
$XDG_CONFIG_HOME/tuiblick/
  awg/awgN.conf
  openvpn/<sanitized>.ovpn
  profiles.yaml
```

AWG files use short interface-safe names such as `awg0.conf`. For OpenVPN,
`sanitize(name)`: lowercase, `[^a-z0-9-_]` → `-`, collapse dashes,
trim, fallback `profile`, dedupe with `-2`, `-3`. The original
filename is kept verbatim in `profiles.yaml` (`original_filename`).

## Existing profiles

Earlier macOS builds used `~/Library/Application Support/tuiblick/`.
The new default is `~/.config/tuiblick/`; existing files are not moved
or imported automatically. You can import profiles into the new directory
with `i`, or keep using the old directory by setting its parent as the base:

```sh
XDG_CONFIG_HOME="$HOME/Library/Application Support" tuiblick
```

This setting applies to that invocation only. Existing VPN connections
keep running; stop a connection with the build and profile directory that
started it before testing connections from a different directory.

## Keys

Press `?` in the app for the full table. Essentials:

| Key        | Action                                            |
|------------|---------------------------------------------------|
| `j/k`, ↑↓  | move in list / scroll detail                      |
| `Ctrl+j/k` | move selected profile down/up (order persists)    |
| `Tab, 1/2/3` | switch pane focus                               |
| `Enter/c`  | connect selected (`c` clears the log *view* when the OpenVPN detail pane is focused) |
| `C`        | connect all in list order (skips busy/missing, stops on error) |
| `d`        | disconnect selected profile's tunnel            |
| `D`        | disconnect all tunnels, newest first (stay open)|
| `Del/Bksp` | delete profile (confirm)                        |
| `r`        | rename selected profile (rescan is automatic)     |
| `i`        | import file (path prompt, `Tab` toggles backend)  |
| `/`, `f`, `s` | filter logs / follow toggle / save log to `/tmp` |
| `?`        | help popup                                        |
| `q`, Ctrl-C | quit — tunnels left running (confirm if any is up) |
| `Q` | disconnect every tunnel, newest first, then quit          |

## Notes you must know

- **Quit leaves the tunnel up.** Quitting with an active tunnel asks
  `active tunnel will stay up after quit. Quit anyway? y/N`.
  Stopping is always explicit (`d`). There is no auto-reconnect,
  no daemon, no launch-at-login in MVP. After a reopen the runtime
  state is clean while the interface lingers: a single `Enter` on that
  profile reports `` `awg0' already exists ``, and connect-all (`C`)
  skips the lingering profile as busy instead of stopping. On Linux,
  a reopen instead adopts a lingering AWG tunnel outright: the profile
  shows `connected (adopted)` (started outside this session), and
  polling, `d`, and exit-IP work as usual.
- **Sudo password lives in memory only.** First connect that needs
  privilege opens one masked prompt per session (`sudo: root |
  sudo cached | sudo needed` in the header). The password is zeroized
  on quit and on auth failure; it is never written to disk.
  Running the TUI itself as root skips prompts entirely.
- **Header:** `init <initial-ip> (<gateway>/<if>) → exit <current-ip>`.
  `resolving…` = probe in flight, `unknown` = IP probe failed,
  `n/a` = route probe failed. Probes never block the UI. Route source is
  platform-specific: `route -n get` on macOS, `ip route` on Linux (each
  with the other platform's commands as a last-resort fallback, so a box
  with iproute2mac or without `ip` still gets an answer when possible).
- **`.ovpn` with a `daemon` directive:** the UI warns (status bar +
  log header) and stays foreground — a daemonized child would break
  log capture and SIGTERM shutdown.
- **Known limitation — unexpected child exit:** if the `openvpn`
  child dies on its own (e.g. `kill -9`), the UI keeps showing the
  last logs until you press `d`. `openvpn.rs` exposes no
  non-consuming liveness poll (needs new API + tests; deferred
  beyond MVP wiring on purpose).
- **Naming note:** spec §8 spells the error field `stderr_tail`;
  the code calls it `tail` because AWG captures *combined*
  stdout+stderr output (parked Task 1 ruling: plan's combined-output
  `tail` governs). Same data, last 2 KB.

## Manual test checklist

1. **Import with weird names.** `i`, import an AWG conf (and, on macOS,
   an `.ovpn`) whose names contain spaces, parentheses, and unicode
   (e.g. `My Office (1).conf`, `café vpn.ovpn`). Expect: copied
   into place — `awg/awgN.conf` for AWG (short interface-safe names,
   since `awg-quick` derives the interface from the file stem) and
   sanitized names for OpenVPN — `original_filename` kept verbatim,
   both listed with readable display names. (Typing a path ending in
   `.ovpn`/`.conf` flips the backend switch as you type; Tab overrides
   it — whatever the switch shows at Enter wins.)
2. **Connect/disconnect each backend** (OpenVPN half: checked on macOS, not on Linux so far).
   `Enter` on the AWG profile →
   `connected`: the right pane splits in two — status + peer block
   left, interface block right — exit IP, follow, and scroll offset
   live in the panel titles, header `exit` IP updates.
   `d` → `disconnected`.
   Repeat for OpenVPN → live timestamped logs; both tunnels may stay
   up together (one per backend). With both up, the right side splits
   vertically — AWG status over OpenVPN logs — and the selected
   profile's panel gets the highlighted border. Connecting while the
   same backend is up prompts to switch (old tunnel stops first).
   `Q` brings everything down (newest tunnel first) and exits;
   a failed disconnect aborts the quit and shows the error.
   `C` connects every profile in list order (same-backend-busy and
   missing files are skipped, first real failure stops the batch).
3. **Sudo prompt appears once.** Fresh session, non-root, no cached
   password: first connect opens the masked prompt once. Type a
   **wrong** password → re-prompt with an error note (exactly one
   re-prompt); type the right one → connects, no further prompts
   this session, no hang. Passwords with trailing newline/unicode
   must work (single trailing `\n` is piped on stdin, EOF after).
4. **Spaced-path `awg-quick up` works.** Connect the profile imported
   from a path with spaces (step 1). Expect success: the full stored
   path travels as one argv element, never shell-split.
5. **`.ovpn` containing `daemon`** (not checked on Linux so far). Connect it. Expect: warning in
   the status bar + log header, child stays foreground-captured
   (logs keep flowing).
6. **`kill -9` the openvpn child** (not checked on Linux so far). Find the child pid, `kill -9` it.
   Expected (known limitation): logs freeze, UI stays responsive;
   press `d` → `openvpn exited (code signal)…`. No panic, no hang.
7. **Missing-file badge.** Delete a stored file under
   `$XDG_CONFIG_HOME/tuiblick/` (default `~/.config/tuiblick/`) by hand
   and wait a few seconds. Expect the
   entry shows `(missing)` (picked up by the automatic rescan);
   connecting to it gives a clear error, not a panic.
   Files on disk with no mapping auto-register the same way.
7b. **Rename.** Select a profile, press `r`, edit the name, Enter.
   Expect: the list shows the new display name; the stored file is
   untouched. Blank names are rejected with an error.
8. **No network.** Disconnect Wi-Fi (or block `api.ipify.org` +
   `myip.opendns.com`). Expect: `unknown` exit-IP / `n/a` route
   with the reason in the status bar; UI still renders and
   connect/disconnect still works. Reconnect network → next
   connect/disconnect resamples.
9. **tmux + terminal smoke at 80x24.** Run inside tmux and in a
   plain terminal window sized 80x24 (Terminal.app on macOS, your usual
   terminal on Linux). Expect: no panic, all
   popups (`?`, sudo, import, confirm, error) render and dismiss
   (`q/?/Enter/Esc`), list + detail + status bar visible.
10. **Different-version `awg show`.** If available, point at a box
    with another AmneziaWG version. Expect: raw text always shown,
    parse never fails the 3 s poll (garbage → `peers: 0`, no error).
    On Linux the interface line reads `interface: awgN` (config stem);
    on macOS it reads `interface: utunN` — both render the same way.
